AI Prototypes Playground

An app to enable quick prototypes through Claude code using real data.

I created an app that allows designers to build quick prototypes using the real design system components, styles and tokens. It uses a set of skills along with MCPs to create prototypes and templates using Figma designs or free prompting ideas. It also has a set of features to include real data in prototypes using the Zalando API.

The challenge

Figma prototypes are time-consuming and limited

Creating prototypes using Figma has many limitations, like using real data, gestures and interactive states, among many others. It can also take a long time to get something working, and in complex prototypes, they are hard to update later or share so others can expand on it. Besides this, there’s no simple way to document how they are wired up, their functionality and features.

Prototyping with production components

I created a node app using Claude code, where I connected our npm registry with all the components available in code from the Zalando design system. I also included Figma code-connect for each component that exists in

This app uses a couple of MCPs to build prototypes like:

  • The official Figma MCP and the Figma console MCP that can accurately read designs from Figma that utilise elements from the design system, such as components, tokens, and styles.
  • Chrome dev tools MCP to automate QA firing a test session where the app compares the Figma design against what's built in the browser using screenshots
  • Github MCP to scan remote repositories and find reusable patterns using the zds components, like login flows, checkout pages and motion implementation that are not part of the system yet. It is also used to reuse other repositories, such as assets and design tokens, which exist on separate projects from the component's code base.

Claude code skills + pulling real data

The prototypes playground uses a set of skills to:

  • Create new prototypes from Figma URLs or freely prompt ideas, or use external sources as references. This skill also asks if the user wants to retrieve live data from Zalando URLs like product detail pages, catalogues, images and video assets, brand and product names, prices, etc. It uses a couple of scripts to pull the data and download assets like videos that are used as blob elements in the browser. The script uses real product videos, downloads the asset, encodes a useful format for the local host browser and deletes the raw video before closing the task.
  • Add prototypes as Templates using placeholder elements and layout mimicking the most used pages in Zalando, for web and mobile (mocked in the browser).
  • Add zds components that only exist in the Figma library or that are custom components but useful to reuse in more than one prototype.
  • A Figma skill that runs internally when building prototypes. This skill runs in a loop using the Chrome dev tool MCP, taking screenshots of what is in the Figma URL passed and comparing it against the implementation in progress. This loop runs 3 times until every difference is sorted, closing the task or asking the user for more input if necessary.

This set of skills helps designers build confidently creesn and views with accurate results, especially when Figma designs are used as starting points. But even when a designer prompts a free idea, or uses a reference, the skills will apply the elements like buttons or image gallery to the closest Zalando components, maintaining the overall coherency with the live Zalando experience and the Brand strategic elements.

Useful add-ons

The app also features a couple of add-ons to help explore alternatives in the browser without expending tokens or prompting variations:

  • Agentation is used to log multiple fix requests on a single prompt, pointing the agent to the exact elements that need to be updated or fixed.
  • Dialkit to allow designers to explore variations of the current prototype implementation without running a new prompt. This allows changing product data, layout, showing or hiding elements, changing variants of components, etc. All of this happens in the browser, so users can freely explore new ideas on the fly.
  • A built-in feature to pull real data using a Zalando URL. Through a user token generated per session, a designer can use a full set of products from a Zalando Catalogue, or a complete Product detail page (PDP), getting brand and product details, price, discounts, delivery details, etc.

The payoff

Even though it is early days for this project, we are already seeing big outcomes in relation to reducing the time to produce a prototype from days to hours. There has also beeing big reduction in design to engineering handoff and improved communication when discussing new features thank to the capacity of the app to include high fidelity functionality like mocking chat-assisted interfaces and simulating the whole journey of a customer, just providing a couple of screens and prompting the states in between.
